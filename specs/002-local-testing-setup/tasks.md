**Input**: Design documents from `/specs/002-local-testing-setup/`
**Prerequisites**: plan.md, spec.md, research.md, data-model.md, contracts/runner-cli.md, quickstart.md

**Tests**: No new automated test suite is requested. Use ShellCheck, the existing QML suite, and the manual nested-compositor scenarios in quickstart.md.

**Organization**: Tasks are grouped by user story so startup, orientation/navigation, and failure/limitations can be implemented and checked as increments.

## Format: `[ID] [P?] [Story] Description`

- **[P]**: Can run in parallel (different files, no dependencies)
- **[Story]**: Which user story the task belongs to (US1, US2, US3)
- Every task includes its target file path.

## Dependencies & Execution Order

### Phase Dependencies

- **Setup (Phase 1)**: No dependencies; T001 and T002 can run in parallel.
- **Foundational (Phase 2)**: Depends on Setup; blocks all user stories.
- **User Story 1 (Phase 3)**: Depends on the runner lifecycle in Phase 2.
- **User Story 2 (Phase 4)**: Depends on the running nested session from US1.
- **User Story 3 (Phase 5)**: Depends on the runner from US1; its documentation task follows US2 because both update the quickstart.
- **Polish (Phase 6)**: Depends on all implementation stories.

### User Story Dependencies

- **US1 (P1)**: Can start after Foundational; establishes the local session.
- **US2 (P1)**: Depends on US1's nested session; adds orientation and flow validation.
- **US3 (P2)**: Depends on US1's runner; US2 and US3 implementation can otherwise proceed independently until shared documentation is updated.

### Parallel Opportunities

- T001 and T002 touch different files and can run in parallel.
- T008 and T009 touch different files and can run in parallel after US1 defines the session entry point.
- T013 and T014 are independent validation tasks and can run in parallel.

## Implementation Strategy

### MVP First (User Story 1)

1. Complete Setup and Foundational phases.
2. Implement US1 and validate local startup, host-session isolation, and cleanup.
3. Stop and verify the setup is useful before adding orientation/navigation checks.

### Incremental Delivery

1. Add US2 for orientation and Home → app → Home validation.
2. Add US3 for useful failure diagnostics and clear fidelity limits.
3. Run ShellCheck, the existing QML suite, and the complete quickstart.
